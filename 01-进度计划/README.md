# 01-进度计划

> 各专业月度工作计划表与进度表的归口目录。计划是督察节点的来源之一，但事项执行状态只在 [工作事项总台账](../04-进度督察/工作台账/工作事项总台账.md) 维护。

## 一、目录结构

```text
01-进度计划/
├─ _模板-月度工作计划表_模板v2.xlsx      权威模板（下划线前缀 = 模板，不参与归档）
└─ 月度计划表/
   ├─ 月度计划上交情况.xlsx              汇总台账：各专业是否按期上交
   ├─ YYYY.MM/                          按月归档
   │  ├─ <专业>月度工作计划表_<负责人>.xlsx
   │  ├─ 土建/                          土建专项独立子目录
   │  └─ 月度计划协调会优化后的版本/       协调会后的修订版（仅 2026.09 起）
```

- **月份目录**一律 `YYYY.MM/`；土建专项计划放该月 `土建/` 子目录。
- **权威模板**为 `_模板-月度工作计划表_模板v2.xlsx`。新专业交表应基于该模板；历史表中出现的其他模板副本（如 `月度工作计划表_模板v2_段伟.xlsx`）是各专业填报件，不是权威模板。

## 二、源表与协调会版本的权威关系

`月度计划协调会优化后的版本/` 存放月度计划协调会后的修订件，文件名以 `_进度通过审查`／`_进度未过审查`／`_现场修改`／`_进度重新审查` 等后缀标注审查结果。

判定权威版时按以下原则，不要只看文件名：

1. 审查结果后缀（未过审查 < 通过审查）；
2. 同名文件的实际修改时间（新者优先）；
3. 该专业源表仍在月份根目录时，**协调会修订件不自动取代源表**——两者职责不同：源表是专业提交件，修订件是协调会结论件。需要确认权威版时以负责人回传和总经办确认为准。

## 三、历史文件名不重命名

月份目录中存在带 `(1)(2)(3)` 等原始接收后缀的文件（如 `2026.08/土建/4600   8月份计划表(3).xlsx`、`2026.07/4600纸机7月份推进进度表(1) 王隆春.xlsx`）。

这些后缀是微信／邮件接收时的**原始文件名**，重命名会破坏与来源的对应关系，因此按根 README 5.3 节保留原名，不做批量重命名。`check_repo.js` 会把它们计入“重复下载后缀”清单（当前 16 个），属已登记的历史告警，不是待处理待办。

> 判定口径：半角 `(1)(2)(3)` 与全角 `（1）`～`（999）` 算下载计数；全角括号内 4 位以上数字（如图纸 `（20260507）…dwg`）是文档日期标注，不算违规。
