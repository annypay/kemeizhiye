# 00-临时存放 — 文档起草区使用规则

> 本目录是**拟稿区**：正在编辑、尚未定稿、尚未正式归档的文件统一放这里。

## 一、什么时候放这里

- Agent 或你刚生成的新文档，还未最终确认；
- 你计划手工修改的文档（改完再入库）；
- 从微信/邮件收到的文件，尚未决定归类。

## 二、状态标记（文件名末尾）

| 状态 | 用法 |
| --- | --- |
| `【待编辑】` | 初稿，等你或 agent 继续改 |
| `【待确认】` | 已改完，等你看一遍定稿 |
| `【待归档】` | 你已确认，说一声"入库"或"归档"即由 agent 处理 |

示例：`20260820-大门方案-v2【待归档】.docx`

## 三、会议纪要临时包（强制规则）

会议纪要不在临时区根目录平铺。每期按会议**实际日期所在自然周**建立独立会议包：

```text
00-临时存放/会议纪要/YYYYMMDD-YYYYMMDD/
```

例如会议在 2026 年 8 月 31 日召开，目录为 `00-临时存放/会议纪要/20260831-20260906/`。会议日期、归档周期、汇报统计期、计划执行期和草稿创建日期不是同一概念：归档周期只用于会议包、汇报、纪要、PPT 和名单的共同前缀；录音目录仍使用实际会议日期 `YYYY-MM-DD`。

| 文件 | 临时区命名 |
| --- | --- |
| 转录草稿 | `<归档周期>-董事长例会-转录草稿【待编辑】.md` |
| 董事长版 | `<归档周期>-董事长例会纪要-董事长版【待确认】.md/.docx` |
| 总经理版 | `<归档周期>-董事长例会纪要-总经理版【待确认】.md/.docx` |
| 完整版（群发） | `<归档周期>-董事长例会纪要-完整版（群发）【待确认】.md/.docx` |
| 待确认事项 | `<归档周期>-董事长例会-待确认事项【待确认】.md` |

创建命令：

```powershell
& "C:\Program Files\nodejs\node.exe" scripts/create_meeting_package.js 2026-08-31
```

会议草稿和三版纪要必须含 `MEETING-MINUTES-META` 元数据。完整规则、表格范式和校验命令见 [会议纪要 README](../03-例会汇报/董事长例会/会议纪要/README.md)。

## 四、入库流程（由 Agent 执行）

1. 你确认后说"**入库**"；
2. Agent 执行：
   - 按内容归入 `01-` ~ `09-` 对应目录，按命名规范正式命名；
   - 若你手改了 docx/xlsx：以**你的终稿为准**，提取差异回写 md 源头版；
   - 更新 `INDEX.md` 索引、必要时更新 README；
   - git 提交并推送。
3. 会议纪要经确认后，三版无状态标记的 md/docx 移入正式纪要目录；转录草稿移入 `_archive/会议纪要/<归档周期>/`；待确认事项在被登记或明确不纳入台账前保留在临时会议包。
4. 其他文件入库后临时区文件删除，正式区只有一个权威版本。

## 五、三条铁律

1. **临时区文件不自动提交 git**（避免半成品入库）；
2. **归档以你的终稿为准**（你改了 Office 版就回写 md，没改就用 md 生成 Office 版）；
3. **超过 30 天未归档的文件**，agent 会提醒你处置（归档或删除），不会悄悄归档。

## 七、快速定位

- 找正在改的文件 → 本目录；
- 找某期纪要草稿 → `会议纪要/<归档周期>/`；
- 找待定去向的 CAD 总图 → `图纸/`；
- 找历史替代稿 → `../_archive/临时区替代稿/`；
- 找正式文件 → 先看根目录 `README.md` 的分类导航，再看 `INDEX.md` 全文索引。
