# 00-临时存放 — 文档起草区使用规则

> 本目录是**拟稿区**：正在编辑、尚未定稿、尚未正式归档的文件统一放这里。

## 一、什么时候放这里

- Agent 或你刚生成的新文档，还未最终确认；
- 你计划手工修改的文档（改完再入库）；
- 从微信/邮件收到的文件，尚未决定归类。

## 二、状态标记（文件名末尾）

| 状态 | 用法 |
| --- | --- |
| `【待编辑】` | 初稿，等你或 agent 继续改 |
| `【待确认】` | 已改完，等你看一遍定稿 |
| `【待归档】` | 你已确认，说一声"入库"或"归档"即由 agent 处理 |

示例：`20260820-大门方案-v2【待归档】.docx`

## 三、入库流程（由 Agent 执行）

1. 你确认后说"**入库**"；
2. Agent 执行：
   - 按内容归入 `01-` ~ `09-` 对应目录，按命名规范正式命名；
   - 若你手改了 docx/xlsx：以**你的终稿为准**，提取差异回写 md 源头版；
   - 更新 `INDEX.md` 索引、必要时更新 README；
   - git 提交并推送。
3. 入库后临时区文件删除，正式区只有一个权威版本。

## 四、三条铁律

1. **临时区文件不自动提交 git**（避免半成品入库）；
2. **归档以你的终稿为准**（你改了 Office 版就回写 md，没改就用 md 生成 Office 版）；
3. **超过 30 天未归档的文件**，agent 会提醒你处置（归档或删除），不会悄悄归档。

## 五、快速定位

- 找正在改的文件 → 本目录；
- 找正式文件 → 先看根目录 `README.md` 的分类导航，再看 `INDEX.md` 全文索引。
