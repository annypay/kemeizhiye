# 03-例会汇报（董事长例会）

> 董事长周例会的全套材料归口。**会议实际日期**是归档周期的唯一计算源：会议日所在自然周（周一至周日，格式 `YYYYMMDD-YYYYMMDD`）决定会议包、汇报、纪要、PPT 和名单的共同前缀；录音目录只用实际会议日期。

## 一、子目录职责

| 子目录 | 命名 | 职责 |
| --- | --- | --- |
| [`各专业汇报内容/`](各专业汇报内容/) | `YYYYMMDD-YYYYMMDD/` | 各专业负责人提交的周汇报原件 |
| [`会议纪要/`](会议纪要/README.md) | `YYYYMMDD-YYYYMMDD/` | 正式签发的三版纪要（董事长版／总经理版／完整版群发）+ Word 打印稿；编制规范见该目录 README |
| [`例会PPT/`](例会PPT/) | 无（历史平铺） | 董事长例会汇报 PPT |
| [`会议录音/`](会议录音/) | `YYYY-MM-DD/` | 实际会议日期录音（**不是**归档周期） |
| [`周例会名单/`](周例会名单/README.md) | `<归档周期>-周例会名单.xlsx` | 参会名单，纪要 `roster_source` 的事实来源 |

## 二、归档周期 vs 实际会议日期

| 概念 | 格式 | 用途 |
| --- | --- | --- |
| 会议实际日期 `meeting_date` | `YYYY-MM-DD` | 录音目录名、纪要编号 `JK-HY-YYYYMMDD` |
| 归档周期 `archive_week` | `YYYYMMDD-YYYYMMDD` | 会议包、汇报、纪要、PPT、名单的目录与文件前缀 |
| 汇报统计期 / 计划执行期 / 汇总截止日 | 各为独立字段 | 只在纪要元数据记录，**不替代**归档周期 |

例：会议 2026-08-31（周一）→ 归档周期 `20260831-20260906`，录音目录 `会议录音/2026-09-01/`（实际开会日）。

## 三、历史目录不重命名

`各专业汇报内容/` 与 `会议纪要/` 下存在历史命名目录：`20260819`、`2026824830`、`20260824830`。

按会议纪要 README 第六节「历史资料兼容」与根 README 5.2 节，**历史周目录不迁移、不重命名**，新建周期不得复用其非标准格式。校验历史会议包时由 `check_meeting_minutes.js` 自动识别并豁免现代化规范（只核对三版齐备与 Word 配对）。

## 四、周例会工作链

完整流程见根 README 6.3 节：

```text
会议实际日期 → 归档周期会议包 → 各专业材料 + 月度计划表与未关闭事项
  → 总经办汇总（显式记录汇报统计期/计划执行期/截止日）
  → 董事长例会 PPT + 汇报数据 → 临时三版纪要与待确认事项
  → 经确认正式纪要 → 工作事项台账更新与下周复盘
```

- 报缺核对以根 README 第三节「人员与专业映射」为唯一权威源；
- 会议纪要先在 `00-临时存放/会议纪要/<归档周期>/` 起草，校验通过才入库；
- 待确认事项不进正式纪要目录，也不自动更新台账。
