# 周例会名单

> 本目录存放董事长周例会的参会名单。名单是纪要元数据 `roster_source` 的事实来源，也是核对各专业报缺的基准。

## 一、命名规范

新建名单一律使用**会议实际日期所在自然周**的归档周期：

```text
<归档周期>-周例会名单.xlsx     例如 20260831-20260906-周例会名单.xlsx
```

归档周期为周一至周日，格式 `YYYYMMDD-YYYYMMDD`，与临时会议包、正式纪要、各专业汇报目录使用同一前缀。规则见根 README 5.2 节与 [会议纪要 README](../会议纪要/README.md) 第一节。

## 二、现有文件

| 文件 | 说明 |
| --- | --- |
| `周例会名单202608310906.xlsx` | 2026-08-31 那期实际使用名单（历史命名，含日期与时刻） |
| `周例会名单202608240830.xlsx` | 2026-08-24 那期实际使用名单（历史命名） |
| `周例会名单.xlsx` | **历史基线版，周期不明**，仅作早期模板参考，不得当作现行名单 |

## 三、历史命名不重命名

上表中两个带时刻的历史文件被既有会议包的 `roster_source` 元数据直接引用（例如 `20260831-20260906-董事长例会-待确认事项【待确认】.md` 即指向 `周例会名单202608310906.xlsx`）。

按会议纪要 README 第六节「历史资料兼容」和根 README 5.2 节，**历史周目录与文件名保持不动**，避免破坏既有链接与 Git 历史。需要关联时在元数据中保留其实际路径，不批量重命名。

> 后续新建名单必须使用第一节的标准命名；不要把历史文件名当作新命名的模板。
