# 04-进度督察

> 重大节点进度追踪：把计划节点、会议决策和推进反馈转化为可登记、可通报、可复查的闭环事项。本目录是事项**执行状态**的归口，但状态本身只在 `工作台账/工作事项总台账.md` 维护。

## 一、三个子目录职责

| 子目录 | 职责 | 权威性 |
| --- | --- | --- |
| [`工作台账/`](工作台账/README.md) | `工作事项总台账.md`（执行状态唯一来源）+ `JK-通报编号流水.md`（正式通报编号唯一来源） | **唯一权威** |
| [`节点汇总/`](节点汇总/) | 各专业上报并反馈标注的土建完成节点汇总表，是事项进展的原始事实依据 | 事实依据，非状态 |
| [`通报与处罚存档/`](通报与处罚存档/) | 已签发通报、处罚存档与《重大节点进度督察工作流程.html》 | 已签发件存档 |

## 二、编号边界

- **工作事项编号 `JK-RW-YYYY-NNNN`**：每项唯一，不删除、不复用、不因文件入库自动关闭。分配与状态见 [工作事项总台账](工作台账/工作事项总台账.md)。
- **通报编号 `JK-YYYY-NNNN`**：仅总经办确认**正式签发**后，按 [JK-通报编号流水](工作台账/JK-通报编号流水.md) 递增分配；草案不占用编号。
- 未经用户确认不得签发通报、分配正式编号或执行处罚。

## 三、闭环口径（摘要）

完整流程见 [重大节点进度督察工作流程](通报与处罚存档/重大节点进度督察工作流程.html) 与根 README 6.1 节：

```text
收计划 → 理节点并登记/更新事项（JK-RW）→ 日对照 → 双确认 → 草案核验
       → 确认签发通报（JK 编号）→ 证据归档 → 复查关闭
```

- 反馈“已完成”只可将事项更新为**待复查**；
- **已关闭**必须同时具备复查日期与可定位证据/归档路径；
- 草案、口头反馈、模板或流程示例均不得作为关闭或处罚依据。

## 四、多版本族待裁决

`节点汇总/` 与 `通报与处罚存档/` 存在未定权威版本的多版本文件（如 `土建完成节点汇总v2_20260805.xlsx` 与 `…v2_20260826.xlsx`、`重大节点进度追踪通报v2.docx` 与 `…v2_20260820/v2_20260826`、`江西柯美重要工作推进单.docx` 与 `…v2.docx`）。

这些文件的“当前版”需由总经办确认后，按根 README 5.3 节版本策略处置（保留 1 个当前版，历史版移 `_archive/`）。**在确认前不搬动、不重命名、不删除**，避免丢失督察证据链。
