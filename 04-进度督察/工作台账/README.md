# 工作台账

> 本目录用于把会议决策、计划节点、工作推进单和督察通报转化为可追踪、可复查的在办事项；不替代原始会议纪要、计划、合同或证据文件。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| [工作事项总台账.md](工作事项总台账.md) | 在办事项的唯一执行状态来源 |
| [JK-通报编号流水.md](JK-通报编号流水.md) | 正式签发通报的 `JK-YYYY-NNNN` 编号唯一来源 |

原始计划和反馈表仍归入 `04-进度督察/节点汇总/`；通报及其附件归入 `04-进度督察/通报与处罚存档/`；每条事项在台账中以“来源”和“证据/归档”字段关联它们。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| `待确认` | 已从正式来源提取，但责任、期限、完成标准或事实状态仍待总经办确认 |
| `进行中` | 责任单位或责任人已确认，正在办理 |
| `待复查` | 责任方已反馈完成，待总经办或指定复查人核验 |
| `已关闭` | 已复查通过，且台账中已记录复查日期和证据/归档位置 |
| `暂缓` | 经确认暂不推进，必须写明原因和恢复条件 |
| `已撤销` | 经确认不再办理，必须写明撤销依据 |

常规流转为：`待确认` → `进行中` → `待复查` → `已关闭`。任何事项均不得因为口头反馈直接关闭。

## 更新规则

1. 每项只保留一个 `JK-RW-YYYY-NNNN` 事项编号；新增前先查重并关联来源。
2. 状态、责任、期限、复查或证据发生变化时，同步更新“最近更新”和“说明/下一步”字段。
3. 关闭事项必须先补全复查日期和可定位的证据/归档路径；暂缓、撤销事项必须记录原因。
4. 不删除既有事项编号。事项被取消时更新为“已撤销”，保留来源和处理依据。
5. 修改台账后运行 `node scripts/check_work_ledger.js`；通过后再按 `/repo-publish` 流程提交。
